# Configuration

Gato reads its configuration from environment variables at startup. A value that is not valid stops startup. The error names the variable and, for JSON values, the path of the problem, for example `GATO_TELEGRAM_CONNECTIONS.main.botToken: Required`. Errors do not show the rejected value.

An empty value counts as unset.

## Value formats

| Format   | Example                | Notes                                                                                |
| -------- | ---------------------- | ------------------------------------------------------------------------------------ |
| Integer  | `30000`                | Whole number from -9007199254740991 to 9007199254740991.                             |
| Boolean  | `true`, `false`        | Also `1`/`0`, `yes`/`no`, `on`/`off`, `y`/`n`, `enabled`/`disabled`.                 |
| Duration | `30s`, `5m`, `12h35m`  | Units `d`, `h`, `m`, `s`, `ms`, in that order. A number without a unit is not valid. |
| List     | `a, b, c`              | Comma-separated. Spaces around entries and empty entries are removed.                |
| JSON     | `{"main":{"key":"v"}}` | One JSON value, usually an object keyed by connection name.                          |

Timeouts and other time spans use the duration format. Their names do not have a unit suffix such as `_MS`.

## Variables

| Variable         | Default         | Description                                                                                                                                                                                                                                                              |
| ---------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GATO_DATA_DIR`  | none (required) | Absolute path of the data directory. It must exist and be writable at startup; otherwise startup stops. Gato never uses a different directory. See [Data directory](#data-directory).                                                                                    |
| `GATO_LOG_LEVEL` | `info`          | One of `fatal`, `error`, `warn`, `info`, `debug`, `trace`, `silent`.                                                                                                                                                                                                     |
| `GATO_TIMEZONE`  | `UTC`           | IANA time zone name, for example `Asia/Kuala_Lumpur`. Offsets such as `+08:00` are not valid. Case does not matter: `asia/kuala_lumpur` gives `Asia/Kuala_Lumpur`. Sets today's date, calendar-month windows and operating hours. It does not change stored event times. |

## Data directory

Gato keeps all conversation records in `GATO_DATA_DIR`, one folder per chat:

```
<GATO_DATA_DIR>/<connection>/<chatKey>/
  events.jsonl   the complete record, one JSON event per line, appended only
  state.json     current chat state; operators may edit some fields
  chat.txt       readable copy of the conversation, made from events.jsonl
```

Connection names and chat keys are folder names. They contain only letters, digits, `.`, `_` and `-`, and do not start with `.`. Gato ignores files and folders in the data directory that do not follow this pattern.

At startup Gato reads every chat folder and applies events that a crash left out of `state.json`. A chat whose files cannot be read is logged as damaged. Other chats continue.

### events.jsonl

Each line is one event, for example:

```json
{
  "type": "message",
  "seq": 1,
  "at": 1711935000000,
  "recordedAt": 1711938600000,
  "dedupKey": "tg:1",
  "messageId": "c0",
  "role": "customer",
  "sender": { "id": "u1", "name": "Ali", "known": true },
  "parts": [{ "kind": "text", "text": "Hello" }],
  "delivery": "received"
}
```

`seq` counts from 1 in line order and identifies the event in its chat. Events have no other ID field. `at` is the original sent time and `recordedAt` the time Gato saved the event, both in milliseconds since 1970 UTC. Conversation order is `at`, then `seq`. Do not edit this file.

If the last line has no line end, Gato reads it. When it is a valid event with the next `seq`, Gato adds the line end and keeps the event. Otherwise Gato logs it as an interrupted write and removes it. A line that is not valid elsewhere in the file, or a gap in `seq`, marks the chat as damaged.

### state.json

Operators may edit these fields. The change applies when Gato next reads the chat, for example on the next event:

| Field        | Values                                                           |
| ------------ | ---------------------------------------------------------------- |
| `owner.kind` | `human` pauses the agent; `agent` resumes it. Also `unassigned`. |
| `status`     | `open` or `closed`.                                              |
| `labels`     | A list of label names.                                           |

Keep the file valid JSON. Do not edit other fields. A `state.json` that is not valid marks the chat as damaged until it is repaired.

Gato reads `state.json` again just before it writes it after new events. An edit saved in the short time between that read and the write is lost. Check the file after an edit while the chat is active.

### chat.txt

One line per message or internal note in conversation order, with time in `GATO_TIMEZONE`, the UTC offset and the sender. Lines after the first line of a message start with two spaces. Internal notes and internal triggers are marked as internal and are never sent to the customer. Delivery states other than received or confirmed show in brackets.

```
[2024-04-01 09:30:00 +08:00] Customer (Ali): Hello
[2024-04-01 09:31:00 +08:00] Agent: Hi Ali, how can I help?
[2024-04-01 09:32:00 +08:00] Agent [uncertain]: Are you there?
[2024-04-01 09:33:00 +08:00] Internal note (comment, by operator): Returning customer
```

A sender that the channel cannot confirm shows as `(unknown sender)` or `(<name>, unconfirmed)`. Gato writes the whole chat.txt again after new events, and at startup when it is missing or when `state.json` does not include the last events.

## Logs

Logs are JSON lines. Gato replaces the value of these fields with `[redacted]`, at any depth, including fields of logged errors:

- Credentials: field names that end with `token`, `secret`, `password`, `authorization`, `apikey`/`api_key` or `signingkey`/`signing_key`/`signingkeys`/`signing_keys`, in any case. For example `botToken` and `webhookSigningKeys` are redacted, `inputTokens` is not.
- Personal data: fields named `text`, `caption`, `phone` or `email`.

A circular reference shows as `[Circular]`. The log message itself is not redacted, so it must not contain credentials or personal data.
